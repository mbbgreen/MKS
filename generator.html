۱

متغیرهای Railway

این چهار متغیر همان‌هایی هستند که entrypoint.sh می‌خواند. UUID و مسیر مخفی به‌صورت امن و تصادفی تولید شده‌اند؛ با دکمهٔ 🎲 می‌توانی تازه‌شان کنی.

آخرین نسخهٔ پایدار: v26.11.9 — با تغییر نسخه، CORE_URL خودکار ساخته می‌شود.
همین عدد را موقع ساخت دامین، به‌عنوان Target Port وارد کن.
اسلش اول و آخر مهم است؛ خودکار اصلاح می‌شود. فقط حروف انگلیسی، عدد، - _ . /
خروجی آماده برای Railway → Variables → RAW Editor 

    

  


  
  

    
۲
آموزش کامل دیپلوی در Railway + ساخت دامین


    
    
      
  1. 
        فایل‌های پروژه را در یک ریپوی GitHub بگذار.
        ساختار ریپو دقیقاً این باشد (فایل‌ها را از همین پروژه‌ات کپی کن):
        
    project/
├── Dockerfile
├── entrypoint.sh
├── nginx.conf.template
└── site/
    └── index.html
    
        ریپوی Private هم مشکلی ندارد. اگر ریپو نداری: GitHub → New repository → Upload files.
      
    2. 
      
  2. 
        در Railway دیپلوی کن:
        New Project → Deploy from GitHub repo → ریپو را انتخاب کن.
        چون Dockerfile در ریشهٔ ریپو است، Railway خودش با Docker بیلد می‌کند (بار اول اتصال GitHub را تأیید کن).
      
    3. 
      
  3. 
        متغیرها را اعمال کن:
        برو به سرویس → تب Variables → RAW Editor →
        بلوک مرحلهٔ ۱ را کامل پیست کن → Update Variables و بعد تغییرات را Deploy کن.
        
    اگر دیپلوی اول با خطای CORE_URL variable is missing کرش کرد، طبیعی است؛
        متغیرها هنوز اعمال نشده بودند. بعد از Deploy کردن متغیرها، سرویس بالا می‌آید.
    
      
    4. 
      
  4. 
        دامین بساز:
        سرویس → Settings → Networking → Public Networking →
        Generate Domain.
        Target Port را روی 8080 بگذار (همان مقدار PORT). اگر Railway پورت دیگری انتخاب کرد، با ویرایش دامین اصلاحش کن.
        یک دامین مثل your-app.up.railway.app می‌گیری — کپی‌اش کن.
      
    5. 
      
  5. 
        تست کن:
        https://DOMAIN/ باید صفحهٔ «CoreEdge Gateway» را نشان بدهد و
        https://DOMAIN/healthz باید ok برگرداند.
        TLS/443 را خود Railway مدیریت می‌کند؛ کار اضافه‌ای لازم نیست.
      
    6. 
      
  6. 
        برگرد به همین صفحه: دامین را در مرحلهٔ ۳ وارد کن و لینک + کانفیگ اصلی را تحویل بگیر. ✅
      
    7. 
    


    

      🛠 عیب‌یابی سریع
      
    
        
  • «CORE_URL variable is missing» ← متغیرها اعمال/Deploy نشده‌اند؛ مرحلهٔ ۳ آموزش را تکرار کن.
    • 
        
  • «Worker config validation failed» ← UUID خراب است؛ با 🎲 یکی تازه بساز، در Variables جایگزین و Deploy کن.
    • 
        
  • صفحه باز نمی‌شود / خطای 502 ← Target Port دامین با PORT یکی نیست؛ هر دو باید 8080 باشند.
    • 
        
  • صفحه باز می‌شود ولی کلاینت وصل نمی‌شود ← مسیر (SECRET_PATH) در سرور و کلاینت باید دقیقاً یکی باشد (اسلش آخر مهم است)؛ کلاینت باید Xray جدید (v26 به بالا) داشته باشد؛ حالت را روی packet-up بگذار و دوباره تست کن.
    • 
        
  • بعد از هر تغییر متغیر حتماً تغییرات را Deploy کن و صبر کن دیپلوی سبز شود.
    •

          🧩 کانفیگ اصلی کلاینت (JSON کامل Xray)
          

            
            
          

        

        

      


      

        ایمپورت در کلاینت:

        • v2rayNG (اندروید): لینک را کپی کن → دکمهٔ + → Import config from clipboard

        • v2rayN (ویندوز): لینک را کپی کن → Ctrl+V (یا Servers → Import share links from clipboard)

        • iOS: Streisand / Shadowrocket نسخهٔ جدید → افزودن از کلیپ‌بورد

        • یا فایل JSON را به‌عنوان کانفیگ کامل در هر کلاینت Xray-based اجرا کن (SOCKS روی 10808 و HTTP روی 10809).

        ⚠️ هستهٔ کلاینت باید Xray جدید (v26 به بالا) باشد، چون سرور از XHTTP با padding از نوع tokenish استفاده می‌کند.
      


      
🔒 لینک، UUID و مسیر مخفی را فقط برای خودت نگه دار؛ هرکس لینک را داشته باشد می‌تواند از سرویس تو استفاده کند. صفحهٔ استاتوس فقط پوشش ظاهری است.
